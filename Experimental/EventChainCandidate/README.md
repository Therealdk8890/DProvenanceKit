# Experimental Swift event chain candidate

Review only. Independent Swift 6/CryptoKit encoder, incremental builder and verifier; not linked into the production package. The copied contract and fixture file are from Python PR #119 commit 17e48752d0144cc42b1d2d658fbb14b72a4499ef. Fixture blob 7d2aa36dbc1d6f0686cea5853f2ac822d69b6bc4. The missing original specification remains a merge blocker. Candidate P-256 signing, independently pinned key verification and exact full trace coverage now implemented; no public wire decoder, persistence, capture loss or external anchor. Secure Enclave custody is not tested. Swift typed input cannot represent Python's invalid integer types or malformed UTF-8. The JSON scanner compares decoded code points, including escaped pairs, instead of Swift canonical-equivalence string equality. The candidate applies shared payload bounds of 1 MiB UTF-8 and container depth 256, root zero. Other resource limits remain open. Existing normal SDK CI is unchanged.

Candidate CI uses focused SwiftLint correctness rules (runner-installed version printed in CI), Swift 6 complete concurrency checking and warnings-as-errors, and a standalone executable checking all six shared positive chains, entry preimages/hashes and adversarial mutations. This is shared-fixture conformance, not reciprocal wire interoperability. Keep draft until reviewed.
